# Data Model: Automatic Deployment to a Self-Hosted Raspberry Pi

**Feature**: [spec.md](spec.md) | **Research**: [research.md](research.md)

This feature changes one database table, adds a configuration entity and an image file, and
defines the deployment records that the operator and CI work with.

## 1. `BookEmbedding` (database, `book` app): changed

| Field | Type | Before | After | Rule |
|---|---|---|---|---|
| `book` | OneToOne → `Book`, PK | unchanged | unchanged | Cascades on book delete |
| `vector` | pgvector | `vector(384)` | `vector` (no fixed dimension) | Length MUST equal `spec.dimensions` and the vector MUST be finite with norm > 0. It is stored L2-normalized (`normalized_vector`). |
| `input_hash` | char(64) | unchanged | unchanged | SHA-256 of the document text, which includes the document prefix |
| `model` | char(100) | `intfloat/multilingual-e5-small` | `spec.repository` (e.g. `Xenova/bge-m3`) | Taken only from the model setting |
| `model_revision` | char(40) | SHA-1 of the source revision and `:onnx-int8` | `spec.tag` | A 40-hex SHA-1 of the canonical spec, so any change to the setting changes it |
| `updated_at` | datetime | unchanged | unchanged | `auto_now` |

**Migration**: `book/0004_bookembedding_vector_any_dimension`, generated by `makemigrations`,
changes `vector` to `VectorField()`. No rows are deleted. Old 384-dimension rows stay and are
treated as stale.

**States** (per book):

```text
missing ──(book save | startup re-encode)──▶ current
current ──(name/description edited)──▶ stale-text ──(same save, same transaction)──▶ current
current ──(image built with a different model setting)──▶ stale-model ──(startup re-encode)──▶ current
```

- **current**: `model == spec.repository`, `model_revision == spec.tag`, and `input_hash`
  matches the text.
- **Search** only includes `current` rows (Principle V). After a model change, startup
  re-encodes every row before traffic is served (FR-034), so search never sees a partial
  catalog.

## 2. Embedding model spec (configuration, `library/book/embedding_config.py`): new

This is the single definition of the model (FR-030). It is resolved from defaults plus
`BOOK_EMBEDDING_*` environment overrides; an empty value means "use the default". The full
variable list is in [contracts/embedding-model-setting.md](contracts/embedding-model-setting.md).

| Attribute | Default | Validation |
|---|---|---|
| `repository` | `Xenova/bge-m3` | Non-empty `owner/name` |
| `revision` | `4de13258303883538bd53b696b452bf8099f0858` | 40-hex commit (pinned; no branches or tags) |
| `model_file` | `onnx/model_int8.onnx` | Relative path; MUST NOT name an instruction set (`avx2`, `avx512`, `vnni`) (FR-026) |
| `tokenizer_file` | `sentencepiece.bpe.model` | Relative path |
| `dimensions` | `1024` | Integer > 0 |
| `pooling` | `cls` | `cls` or `mean` |
| `query_prefix` | `""` | String |
| `document_prefix` | `""` | String |
| `max_tokens` | `512` | Integer from 8 to 8192 |
| `tag` (derived) | SHA-1 of the canonical JSON of all fields above | 40 hex characters |

Runtime tuning, such as `BOOK_EMBEDDING_THREADS`, is not part of the spec and does not change
`tag`.

## 3. Image model manifest (file in the image): new

`<BOOK_EMBEDDING_CACHE_DIR>/manifest.json` is written by `scripts/fetch_embedding_model.py`.

```json
{
  "spec": { "repository": "...", "revision": "...", "model_file": "...", "tokenizer_file": "...",
            "dimensions": 1024, "pooling": "cls", "query_prefix": "", "document_prefix": "",
            "max_tokens": 512 },
  "tag": "<40 hex>",
  "snapshot_path": "<absolute local path of the downloaded files>"
}
```

**Rules**:
- Runtime loading uses `snapshot_path` only and never contacts the hub (FR-033).
- The system check `book.E001` fails when the manifest `tag` differs from the resolved spec tag,
  and the error names both repositories and revisions. `book.W001` warns when the manifest is
  missing.

## 4. Published image reference (GHCR): new behavior

| Reference | Points to | Moves? | Written by |
|---|---|---|---|
| `<repo>:main` | Newest successful `main` build, both architectures | Yes, but only when `github.sha` is still the head of `main` | `merge` job on `main` pushes |
| `<repo>:sha-<short>` | That commit's build | Never | Every publishing run |
| `<repo>:<semver>` | The version-tag build | Never | `v*` tag runs |

- `<repo>` is `ghcr.io/arezzon/library-django`.
- Each reference is a manifest list holding `linux/amd64` and `linux/arm64`. There is no
  `latest` reference.

## 5. Server stack configuration (Portainer stack environment): new

The operator sets these variables in Portainer; the full table with defaults is in
[contracts/server-stack.md](contracts/server-stack.md).

- **Required secrets**: `SECRET_KEY` and `DB_PASSWORD`.
- **Version selection**: `IMAGE_TAG` defaults to `main`, which means following the newest build.
  Setting it to `sha-<short>` or `<semver>` pins the stack; removing it unpins.
- **Persistent volumes**: `pgdata` (PostgreSQL) and `redisdata` (Redis AOF). They survive
  redeploys and reboots.

The stack is in one of two states:

```text
following-main ──(operator sets IMAGE_TAG=sha-xxxx, redeploys)──▶ pinned
pinned ──(operator clears IMAGE_TAG, redeploys)──▶ following-main
```

## 6. Deployment webhook (GitHub repository secret): new

| Attribute | Value |
|---|---|
| Secret name | `PORTAINER_WEBHOOK_URL` |
| Value | `https://<public portainer host>/api/stacks/webhooks/<uuid>` (POST) |
| Visibility | Repository secret, which only repository admins can set. It is never printed: curl stderr is suppressed, and GitHub masks the value. |
| Absent | The deploy step is skipped with a warning; publishing still succeeds. |
